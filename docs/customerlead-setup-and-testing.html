This guide and the accompanying workflow contain no API keys or CRM tokens. The guide was prepared from a read-only inspection of the saved n8n workflows and local CRM. No live email was sent during preparation.

01 · Understand the system

What each workflow does

Workflow 1 · Original automation

Accepts form inquiries and scans Gmail. It validates leads, uses AI, saves form leads in Sheets, creates Gmail support drafts, sends configured form acknowledgements/owner alerts, and checks eligible follow-ups.

Event publisher nodes report those saved results to the dashboard.

Workflow 2 · Combined bridge

Reads owner changes from the dashboard and updates the shared lead/review rows. It also claims replies that the owner approved and explicitly confirmed for sending.

It sends through Gmail and reports the result back to the dashboard.

09 · Test 4

Receive a Gmail inquiry and AI draft

This test exercises the original workflow’s email support branch. Use a second inbox you control as the customer; the receiving Gmail account is the account selected in your n8n Gmail credential.

  1. In CONFIG — BUSINESS, FAQ & AI MODELS, check the business facts, signature, primary provider and available model. Use the controlled test-sender address in gmail_query; preserve the processing/outcome-label exclusions. Add a CRM TEST subject restriction for this test.
  2. Send a new message from the second test inbox to the connected business Gmail inbox. Suggested subject: CRM TEST — Drain inspection 01. Suggested body: “Can you inspect a blocked kitchen drain? Please let me know what details you need. This is an integration test.”
  3. In the original workflow, run START — Manual Test, which starts the Gmail support path. Alternatively use its configured schedule after publishing. Do not use the form trigger for this email test.
  4. Inspect the Gmail search/read nodes, sender screening, AI response and Review AI & Route result. A valid response can create a draft; a review/skip/failure can take the no-draft branch.
  5. If a draft is created, check Gmail — Create Draft (NEVER SEND) and then Publish Email support processed. Open Gmail Drafts and confirm the draft exists.
  6. Open the dashboard Inbox, select the Gmail source and find the test subject/customer. Check the original message and summary. Open Review reply draft to see the proposed reply, provider and review reason.
  7. If it takes the no-draft path, the second publisher after Gmail — Label No-Draft Outcome should still create the inquiry in the CRM. Create a manual reply when appropriate.
  8. To send an approved reply from the dashboard, follow Test 3: approve, sync the review, confirm sending, run the bridge and verify the received message.

Pass: the original email and its processing outcome appear in the dashboard; a successful draft path also supplies a linked Gmail draft. The support branch creates drafts rather than sending the proposed support reply automatically.

If Gemini or fallback routing fails

The reviewed source has two missing fallback connections. Check and restore:

IF — Primary Gemini?  false → AI — OpenAI Primary

Use valid credentials and supported models for each provider you enable. The primary Gemini request’s error behavior must reach its parser/fallback instead of stopping the workflow before fallback.

Receiving an email does not create follow-up permission. Gmail inquiry leads default to no consent. The dashboard shows processed/published inquiries, not a mirror of every message in the mailbox.
